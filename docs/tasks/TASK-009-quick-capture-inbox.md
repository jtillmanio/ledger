# TASK-009 — 1.4b Quick-capture inbox

## Goal

A half-formed thought ("someone mentioned the Waid FF run") can be saved in ten seconds from anywhere, with nothing required but the text. Unresolved notes wait in an inbox with a count on the dashboard until they are turned into a real book or run.

## Context

- Roadmap: `docs/TASKS.md` § 1.4b Quick-capture inbox (sitting 5, after 1.4c). FEATURES #21 (Part 2b). The roadmap entry and its **Check:** are the contract.
- **Why this is large:** it adds a table (schema and migration) and two UI surfaces, the capture field and `/inbox`, plus the dashboard chip (`workflow.splitPolicy: never-split`). The roadmap's S predates the table, which `docs/FEATURES.md` Part 5 draws but no migration has created yet. The CLAUDE-CODE-PROMPTS hint is Sonnet. This draft says Opus because it is a schema change (the /new-task model rule).
- **Schema change, stop and ask at plan time** (CLAUDE.md): the `inbox` table as FEATURES Part 5 sketches it, `inbox(id serial, user_id → users, raw_text text NOT NULL, kind text, created_at timestamptz NOT NULL DEFAULT now(), resolved_at timestamptz, book_id → books, run_id → runs)`, with `kind` widened to `books | comics | watch | NULL` (NULL is *Unsure*). It is added to `USER_TABLES` in `src/db/export-tables.ts` (Hard rule 7, D-17).
- Architecture: `docs/ARCHITECTURE.md` § 4. Interface — the route table's `/inbox`. 2.15 (resolving routes into the existing add flows, not a third entry path), D-28 (*Save to inbox* is Watch's fallback, used by 8.2).
- Design: mockup `capture` (capture on the left and the unresolved queue on the right on desktop; zero required fields; resolve carries the raw text through as a search term) and `dashextras` (the inbox chip on the lede). FP-D16: from 1024px the sidebar's `Inbox (N)` replaces the chip.
- Decisions: D-28, D-40 (FP-D16), D-17.
- **Settled by the owner, 2026-10-09:**
  1. Until *New Run* exists (3.2), a comics note resolves to Add issues → Search (TASK-006) with the text pre-filled, against the last-touched run (the run chip lets you change it). 3.2 adds *New Run* as a second choice.
  2. This task builds the count and the dashboard chip. 1.8 (TASK-014) places `Inbox (N)` in its sidebar and asserts that half of the check.

## Acceptance criteria

- [ ] AC-1 (roadmap **Check:**, verbatim): test that an inbox row saves with only `raw_text` set, and that resolving it links `book_id` or `run_id` and stamps `resolved_at`. A note tagged Watch resolves into a `/watch/add` URL carrying its text. `/inbox` lists only unresolved notes, newest first, and the dashboard chip and `Inbox (N)` link to it.
- [ ] AC-2: The capture field saves with an empty kind. The kind control is **Books · Comics · Watch · Unsure**, with Unsure stored as NULL. Saving an empty or whitespace-only note is refused with *Write something first* under the field and writes nothing. The migration's `kind` CHECK rejects any other value.
- [ ] AC-3: **Resolve** on a books note opens Add books (TASK-008) with the text as the search. On a comics note it opens Add issues → Search (TASK-006) with the text pre-filled. Completing that add links the note's `book_id` or `run_id` and stamps `resolved_at`, and the note leaves `/inbox`. Cancelling the add leaves the note unresolved.
- [ ] AC-4: Given 3 unresolved and 2 resolved notes, the comics and books dashboards show an inbox chip reading 3 on the lede below 1024px, linking to `/inbox`. With 0 unresolved, no chip renders. `inbox` is in `USER_TABLES`, and `test/export-tables.test.ts` passes.
- [ ] AC-5: The capture field and `/inbox` meet the UX floor (`docs/TASKS.md` § *The UX floor, for every UI task*): `/inbox`'s empty state is a `--raise` panel with one primary action; loading is a skeleton at the loaded size; the field and the kind control have names; **Resolve** is a real button at least 24px; screenshots at every `ui.viewports` width, light and dark.

## Out of scope

- *New Run* (3.2) as a resolution target, and the `/watch/add` screen itself (8.2). The Watch resolve produces the URL only.
- The sidebar's `Inbox (N)` placement (1.8, TASK-014).
- Editing or deleting notes beyond resolving them.
- AI suggestions for what a note refers to (Phase 7).
