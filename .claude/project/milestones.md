# milestones: Ledger

The roadmap (`docs/05-roadmap.md`) stays the source of truth, so this project
runs `/milestones` in coverage mode. The task list (`docs/06-tasklist.md`)
already exists: milestones M1–M25, with M1–M9 the MVP (cutover) and the same
numbers as START-HERE's sittings. On top of the kit's coverage-mode steps:

- After the gate, give each new roadmap entry a row in the milestone it
  belongs to (the next free one if none fits, with a goal, a demo and an order
  line like the others), and bring the tasklist's *Coverage* tables up to date:
  the counts, *Features → milestones* and *Entities → tasks*.
- A new feature gets the next free F-ID in `docs/01-product.md` § Feature
  index, with its roadmap entries. Its priority follows its milestone: MVP for
  M1–M9, Next for M10–M15, Later after.
- Never renumber a milestone or move a row between milestones without the
  owner's approval at the gate: decisions, STATUS and START-HERE cite them.
